# stations/

Station UIs; they read snapshots and send intents, never sim/ (FT-ARC-011). The client's main menu is `app/main_menu.gd` (`MainMenu`): only app/ may name `HostSession`. Once a client is welcomed it hands the `NetClient` to `ClientShell` here.

## Files

| File | Role |
|---|---|
| `client_shell.gd` | `ClientShell`: the session. Polls the client, forwards every event to `VoicePlayer.handle_event` (voice lines) or `CrewState.handle_event`, pumps voice parts, applies Welcome `lang` (`I18n.apply`, `LocalLines`), pushes snapshots into the `SnapshotInterpolator`, resumes a dropped connection with its token, and shows `LobbyScreen` until the pick's ship has started, then the `StationScreen` of the pick, with `PauseOverlay`, `OutcomeCard`, subtitles and `SettingsScreen` on top. |
| `station_context.gd` | `StationContext`: what panels read and send through: `view` (`NetViewState`), `interp`, `crew`, `intents`, `settings`, `matcher`, `clock`; helpers `selection_local()`, `mark_position()`. |
| `crew_state.gd` | `CrewState`: the model built from Welcome, the Catalogue and events: pick, catalogue, lobby, Start, claims, pause, abandon votes, the outcome card and its "Run again" votes (`run_over`), alert, marks (Alpha to Hotel), pings (3 s pulse, copies), and the selection every panel of the client shares. Signals `changed(what)`, `toast(key, args)`, `pinged(ping)` (the ping chime), `sim_event(kind, payload)` (events it doesn't keep: hit, fault, ...). |
| `ship_intents.gd` | `ShipIntents`: the one send seam (alert, marks, pings, claims, picks, Start, votes, commands). Tests swap the client for a recorder. |
| `station_screen.gd` | `StationScreen`: top bar, one disc radar, panels (one focused in the main area, the rest docked), toasts; asks the shell for the menu on Controls (`?`, first visit). Feeds input through `InputMatcher` and routes each intent event by `IntentTable.target`; handles the common actions (`_common`) and the station-less live set (`_live`). |
| `station_alerts.gd` | `StationAlerts`: the own ship's hits, faults, low shields and collision warnings as a toast, an edge flash (`AlertFlash`) and a tone (`AlertTones`) on the stations they affect (`ROUTES`, `DEPENDS`); the ping chime and the alert-level tone (T056). |
| `station_panel.gd` | `StationPanel`: base class of every panel. |
| `station_registry.gd` | `StationRegistry.PANELS`: station id to panel script; unlisted ids get `PlaceholderPanel`. |
| `helm/` | `HelmPanel` (§5.1, T051): cockpit or chase view (`HelmView`), HUD with compass and off-screen arrows (`HelmHud`), `ShieldRing`; the controller radial is `HelmPanel.RADIAL`. The class comments give what it sends and when. |
| `relay/relay_panel.gd`, `relay/relay_map.gd`, `relay/relay_hud.gd` | `RelayPanel`, `RelayMap`, `RelayHud`: Relay (§5.5): the map with probes and their coverage bubbles, routes, hazard zones, flagged lanes and the site banner; mark curation (drag to place on the view plane, Shift+drag depth, drag to move, drop on a contact to attach, N rename, Delete, M attach or free, C centre on the selection, right-drag turn, wheel zoom); P launches a probe to the selection or arms the next click, H the same for a hazard zone, G adds the selection to route 1 (Shift+G clears), L flags lanes, X sends the selected mark to the ship chosen beside SEND, Enter and Backspace accept and decline the oldest inbox mark; the HUD lists probes, contacts, marks, the ship's log and the inbox; controller cursor on the sticks and triggers. |
| `viewer/viewer_panel.gd`, `viewer/status_view.gd` | `ViewerPanel`: the main screen (§5.8): the view `CrewState.main_view` names (forward with the auto-chase, chase, tactical = the radar fills the screen, target = a camera on the selected or nearest contact), `StatusView` for status (hull, shields, subsystem health, objectives, alert; `StatusView.model` is the testable part), callsign rail, wide radar, comfort roll locks, and the card the Captain pinged (10 s). `interactive` is true only inside the Captain's mirror. |
| `captain/captain_panel.gd`, `captain/chip_list.gd`, `captain/chip_source.gd`, `captain/fixture_cards.gd` | `CaptainPanel` (§5.7): a mirror (`ViewerPanel`, interactive), view buttons and keys 1 to 5 (`ShipIntents.set_main_view`), pings and marks into empty slots only, the read-only `ChipList` fed by `ChipSource.open_chips(ctx)` (Section.CHIPS rows when strand G's block exists, else a fixture) and `FixtureCards`, the list of Comms' mission and contract cards from `content/fixtures/comms_cards.json` (fixtures until #10, D190; the Comms half of the joint views reuses it). A ping on a card is `ping("card", id)`. |
| `science/science_panel.gd` | `SciencePanel` (§5.4, E01): orbitable disc radar with icons sized by detection confidence, contact list, `ScienceCard` (a confidence bar per part), passive/active, Scan, Hack, ping, scan-position mark, own-ship scan and the `scan` claim; an open scan or hack replaces the radar with `ScanGame` (silhouette alignment, 1 to 3 axes by drag, keys, sticks or axis chips) or `HackGame` (node route, arrows, d-pad, stick or tap). `ScienceLookup` maps the section's hashed class and damage ids to `content/`. Reads `Section.SCIENCE` (`net/science_view.gd`); every rule is the server's. |
| `placeholder_panel.gd` | `PlaceholderPanel`: name and StationDef read-out (any station without a panel). |
| `comms/comms_panel.gd` | `CommsPanel` (placeholder until #10, D190): the placeholder plus `FixtureCards`, the Comms half of Approach, Parley, Quartermaster, Intel and Ops. |

| `client_settings.gd` | `ClientSettings`: per-client settings in one ConfigFile (`user://client_settings.cfg`, path injectable): name, bindings, UI scale, tips seen, invert pitch, comfort (roll lock deck / target / reference, reduced FOV, the cosmetic reference plane). |

## Adding a station panel

1. Subclass `StationPanel` in `stations/<station>/<station>_panel.gd` and add one line to `StationRegistry.PANELS`.
2. Override what you need: `_setup()` (build children; `ctx` and `station` are set), `_mode_changed()` (focused main view or docked compact view: `focused`, `docked`), `handle_intent(event)` (your group's press and hold intents; return true when handled), `item_at(pos)` (the item under the cursor or reticle for select, ping and mark: `{"kind", "id"}` or `{"kind": "point", "site", "pos"}`), `has_request_chip()` and `send_request()` (B, View+Y), `claim_item()` (K, View+X), `radar_orbitable()`, `mouse_steers()` (the screen feeds mouse motion to the matcher only while it is true; Helm frees the pointer), `cursor_pos()` (where a controller's "under the cursor" points; the centre by default), `full_screen()` (a lone panel that draws its own radar hides the side column: the main screen), `replace_mark(item)` (Relay replaces a mark when all 8 are used).
3. Axes are polled: `ctx.matcher.axis("helm_pitch")`; hold state: `ctx.matcher.is_held("face")` (toggle-aware).
4. Read `ctx.picture()` for the frame's items (world and ship-frame offsets), `ctx.ship_def()` for the ship definition, `ctx.site()` for the own site, `ctx.interp` for interpolated positions (`own_position`, `own_rotation`, `contact_ids`, `contact_position`, `offset_to`, `local`), `ctx.view.blocks[StationViews.Section.X]` for block fields, `ctx.view.claimer(item)`, `ctx.crew.selection`, `ctx.crew.marks`, `ctx.crew.pulse(kind, id, ctx.now_ms())`.
5. Send with `ctx.intents.command({"kind": ...})`, `ctx.intents.claim(item)`, `ctx.intents.place_mark(...)`.
6. Bindings: add rows to `IntentTable.INTENTS` (`input/intent_table.gd`, your station as group) and an `intent.<id>` key in every language of `content/i18n/strings.json`. The menu's Controls and Rebind keys tabs follow.

The layout is fixed: top bar; the focused panel in the main area on the left; the radar and docked panels in a right column. A joint view is the same screen with two panels; F1/F2, hold View + LB/RB, or a click on a docked panel moves the focus (FT-JNT-001). Always-live intents (`IntentTable.is_live`) reach their station's panel whatever the focus (FT-JNT-007). In Tactical with Helm focused the cockpit flies and the KB/M fire buttons reach Weapons, which fires every claimed mount at the selected target (`WeaponsPanel.fire_claimed_at`, FT-JNT-008); with Weapons focused the mouse aims and Helm's rotation stays neutral, so flight assist holds the attitude. A joint view's pick receives the union of its stations' data (FT-JNT-005); a request chip to a station on the same screen runs as the direct action (`StationPanel.send_request`, `_direct`: boost, one more pip for power or sensors, align for bring to bear, the scan mark, fabricate a probe). Toasts sit top-right of the screen (§5.0); the top bar stars the focused station.

## Common actions (§5.0, FT-STN-009)

- Select (click, A): the item under the pointer or reticle; over nothing the click falls through, so LMB still fires in the turret (owner decision in #7).
- Cycle target (T, RB tap): contacts nearest first. Select last pinged (Y, hold RB).
- Ping (middle-click, R3 tap): under the cursor, else the selection. Mark (Shift+middle-click, hold R3): under the cursor, else on the selected contact; refused with a toast at 8 marks; viewers don't mark.
- Accept and decline (Enter / Backspace, X / Y): to the focused panel, else they answer the oldest request chip sent to the screen (`ChipStrip`). Request chip (B, View+Y): the panel's `request_chips()` from `content/chips/chips.tres`: one is sent at once, several open the numbered `ChipMenu` (B, then 1-2); a chip to a station on the same screen runs as a direct action (FT-JNT-005). A panel overrides `chip_arg()` for a chip's argument (Weapons: the mount).
- Radar side strip (Z, View+Left; moved off B by the owner in #7). Claim or release (K, View+X): the focused panel's `claim_item()`.
- Overlay (?, View tap), menu (Esc, Menu).
- Alert (Alt+A cycles; hold View + d-pad; the top bar's chip picker): crew only (FT-STN-008).

## Tests and fixture

`tests/stations/station_fixture.gd` (`StationFixture`): `context(entry)` builds a full `StationContext` with no server: ship 0 "Kestrel" started, a hostile H2 at 4 high 2.3 km, an unknown U3 at 11 high 8 km, an own-faction F4 at 7 level 600 m, mark Bravo at 8 low 1.2 km, a pinned clock (`StationFixture.clock(ctx).ms`) and a `RecordingClient` (`StationFixture.sent(ctx).of("ping")`). Scene tests set `StationScreen.panel_factory` to inject test panels.

L5: `tests/visual/station_shot.tscn` shows the fixture (properties in `station_shot.gd`). Add a shot as a `tests/visual/shots.json` row with `"scene": "res://tests/visual/station_shot.tscn"`, `"size": [1280, 720]` and its `"set"` properties (`view`, `entry`, `selected`, `ping`, `overlay`, `tooltip`, `strip`, `ui_scale`), run `tools/gate.sh l5 --update-baselines`, and check the PNG by eye.
