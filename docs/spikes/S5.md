# S5: 6DOF Helm flight prototype

Run on fugaku (i7-11800H, pinned to two threads), 2026-10-19, Godot 4.7.2-stable. Covers T012 and the NAV-3 extension (plan review NAV-2, NAV-3; D24, D47, D97). Everything here is spike code: the sim part is written to be promoted, the rest is throwaway.

## What was built

`spikes/s5/helm_prototype.tscn` is a cockpit view of one ship, the moving hostile `H2`, the free mark `Bravo` and a friendly station `F1`, with a target compass, a disc radar, contact chips, a flight status panel and a help overlay. The simulation lives in `spikes/s5/sim/` as `RefCounted` classes with no Node, SceneTree, I/O, loading or networking; a scratch copy under a pure `sim/` folder passes `tools/lint_arch.py`, and a negative control (`extends Node`, `load()`) fails it as expected. The scene owns an `S5FixedStep` accumulator and steps `S5World` at a fixed 60 Hz, at most 8 ticks a frame (FT-ARC-006). Visuals interpolate between the last two ticks.

| Part | Files | Role |
|---|---|---|
| Integrator | `sim/integrator.gd`, `sim/ship_body.gd` | Semi-implicit Euler, Euler's equations for a diagonal inertia, quaternion renormalised each tick; thrust and torque clamped to the envelope; propellant spent in proportion to impulse (FT-SIM-001–003, FT-SIM-007) |
| Assist | `sim/assist.gd`, `sim/helm_state.gd`, `sim/thrust_command.gd` | The three holds, face, Level, all-stop, hold-to-approach; only ever returns a thrust command (FT-SIM-004, FT-SIM-005, FT-SIM-036, FT-SIM-037) |
| World | `sim/world.gd`, `sim/item.gd`, `sim/helm_input.gd`, `sim/fixed_step.gd` | Items, the target's script, edge inputs (toggle, select, all-stop, Level) |
| Words | `sim/callout.gd` | Ship-frame clock, height and range words and chip text (FT-SPA-003, FT-SPA-004, FT-SPA-026) |
| Test pilots | `sim/autopilot.gd`, `sim/scenarios.gd` | The scripted intercept pilot and the two headless scenarios |
| Scene and UI | `helm_prototype.gd`, `input_mapper.gd`, `hud.gd`, `compass.gd`, `radar.gd` | Input, cockpit and chase cameras, widgets |
| Numbers | `measure.gd` | `godot --headless --path . -s res://spikes/s5/measure.gd` prints the results below |

## Flight model and modes

Assist is on by default. It computes a body-rate setpoint and a velocity setpoint and turns the errors into torque and force with first-order time constants, clamped per axis to the ship's limits; the integrator then charges propellant for exactly that command, so no mode moves the ship for free. Decoupled (Tab) drops the holds: stick and keys command torque and thrust directly, and a ship with no input keeps its velocity and spin.

| Mode | Input | What assist does |
|---|---|---|
| Holds (assist on) | none | Zero body rates without rotation input; zero lateral and vertical velocity without strafe input; forward speed tracks the throttle setpoint. Strafe input fires that axis at full thrust; W/S and the triggers ramp the setpoint. |
| Face | hold F / L3 | Turns the bow onto the selected item at up to the assist turn rate, braking on a $\omega = \sqrt{2\alpha\theta}$ curve; roll stays manual. Works in decoupled too (FT-HLM-006). |
| Level | L / View+X | Rolls so the ship's up is as close to ecliptic up as the heading allows; a second press, or a press when already rolled level, also pitches onto the ecliptic (D97). Clears when within 0.3° or on stick input. |
| All-stop | Space / View+B | Latched: drives velocity relative to the site and all rotation to zero, sets the throttle setpoint to 0, and ends at rest ($<0.05$ m/s, $<0.002$ rad/s) or on any manual input (FT-SIM-036, FT-HLM-014). |
| Approach | hold X / B | Faces the selected item and flies a velocity of item velocity plus a closing speed $\min(\sqrt{2 b\,g}, g/4\,\mathrm{s}, 300)$ along the line of sight, $g$ being the gap to the 500 m stand-off and $b$ half the retro acceleration. Releasing hands back control at the current forward speed (FT-SIM-037). |

All-stop, approach and face also run in decoupled mode, since they are explicit assist actions (provisional).

## Controls

The help overlay (H, F1 or Start) lists them in the game. Input actions are added to the `InputMap` at run time, so `project.godot`'s input map is untouched. Keys use physical key codes, so WASD works on any layout.

| Action | Keyboard and mouse | Controller |
|---|---|---|
| Pitch and yaw | mouse, arrow keys | left stick |
| Roll | Q / E | hold LB + left stick left/right |
| Speed setpoint up / down (decoupled: thrust) | W / S | right / left trigger |
| Slide sideways, up and down | A D, R V | right stick |
| Face selected (hold) | F | L3 |
| Approach selected (hold) | X | B |
| All-stop | Space | View + B |
| Assist on/off (decoupled) | Tab | View + A |
| Level | L | View + X |
| Select next (H2, Bravo, F1) | T | X |
| Move Bravo 5 km ahead / here | M / Shift+M | A (ahead) |
| Radar range 2 / 10 / 50 km | Z | d-pad up |
| Chase camera | C | Y |
| Invert pitch | I | |
| Restart | Backspace | View + Start |
| Fullscreen, free the mouse | F11, Esc (click recaptures) | |

The mouse drives a virtual stick that re-centres with a 0.12 s half-life, so the turn rate follows mouse speed and the nose stops when the mouse stops; a green dot shows the deflection. Pitch is not inverted on any device; I inverts it (provisional). Sticks have a 0.2 dead zone and triggers 0.1, rescaled by the `InputMap`.

## Widgets

| Widget | What it shows |
|---|---|
| Target compass (bottom centre) | A dot for the selected item at the $(x, y)$ of its unit direction in the ship frame: centred means dead ahead (or dead astern), filled when ahead, hollow when behind (FT-HLM-003) |
| Disc radar (bottom right) | The deck plane seen from a fixed angle (squash 0.42), bow at 12, clock ticks every 30°, a ring at half range. Each item has a stem from its foot on the disc: solid blip with the stem up when above, hollow with the stem down when below, a diamond for the mark. A ring passes through the selected item's foot, the selected item is drawn last, items past the range are arrows on the rim, and very tall stems are clamped to the widget (FT-SPA-007, 008, 024, 025). Z cycles 2, 10 and 50 km. |
| Contact chips (top right) | One chip per item in the ship frame, as spoken: `H2 · 4 high · 2.3 km ▲closing`; beyond ±60° elevation only `overhead` or `under`; the selected chip is boxed (FT-SPA-003, FT-SPA-026) |
| View markers | Brackets on contacts and a diamond on the mark with name and range; prograde and retrograde markers; the ecliptic drawn as a faint horizon ring, so Level can be judged |
| Status (bottom left) | Assist or DECOUPLED, speed and forward speed, throttle setpoint, propellant, active mode, selection, and an intercept timer that freezes when H2 first comes within 100 m |
| Thrust bars | This tick's command as a share of each axis' limit (forward, side, vertical, rotation) |

A field of dust specks within 300 m of the ship gives the sense of speed and drift; stars at 60 km give attitude.

## Tuning used

All values are provisional and in code; M1 moves them to ship data (FT-SIM-002).

| Ship | Value |
|---|---|
| Mass | 50 t |
| Inertia (pitch, yaw, roll) | 2.0, 2.4, 1.2 × 10⁶ kg m² |
| Main drive, retro | 1.0 MN (20 m/s²), 0.5 MN (10 m/s²) |
| Lateral and vertical, each way | 0.6 MN (12 m/s²) |
| Torque (pitch, yaw, roll) | 3.0, 3.6, 3.0 MN m (1.5, 1.5, 2.5 rad/s²) |
| Propellant, exhaust velocity | 10 t, 60 km/s (used = impulse / exhaust velocity; torque counts as force over a 10 m lever arm) |

| Assist | Value |
|---|---|
| Turn rate cap (pitch and yaw, roll) | 40°/s, 90°/s |
| Rate hold, velocity hold, attitude time constants | 0.12 s, 0.4 s, 0.3 s |
| Attitude braking | 60 % of the angular acceleration |
| Speed setpoint range, ramp at full input | −50 to 300 m/s, 60 m/s per s |
| Approach stand-off, cap, braking, final time constant | 500 m, 300 m/s, 50 % of retro (5 m/s²), 4 s |

The target starts 5.6 km away, above and to port, at $(−3000, 1500, −4500)$ m, flies at $(110, 0, 30)$ m/s and weaves ±120 m on two axes with a 30 s period, so 114–140 m/s and at most 7.4 m/s² of lateral acceleration, below the ship's 12 m/s². A first version with a ±300 m, 25 s weave needed 19 m/s², more than the ship can follow, and approach could not match it (34 m/s left at 120 s).

## Results

`tests/spikes/s5/` has 16 gdUnit4 cases, 0.3 s in total. They drive `S5World` tick by tick. Intercept means H2 within 100 m (provisional); the autopilot produces only stick and throttle input with assist on.

| Scenario | Result |
|---|---|
| Intercept from rest, facing −Z | 35.4 s, 43 m/s relative at capture, 541 kg propellant |
| Intercept from rest, facing away | 37.1 s, 42 m/s, 532 kg |
| Intercept drifting 120 m/s to port, facing port | 35.6 s, 43 m/s, 649 kg |
| All-stop from 185 m/s tumbling at 0.62 rad/s | at rest after 17.6 s, 1.36 km travelled |
| Then hold-to-approach to Bravo, 6.0 km away | at rest within 1 km after 59.7 s; after 90 s and a release, 500 m from Bravo, 0.011 m/s, no rotation; 606 kg for both |
| Hold-to-approach on the weaving H2 from the start | within 1 km at 32.5 s; at 120 s 499 m off, 0.6 m/s relative |
| Sim tick (assist and integrator, approach held) | 8.7 µs |

The other cases cover constant thrust against $x = \tfrac12 a t^2$ (to within one step's $a\,t\,\Delta t$), zero input keeping velocity, spin and propellant, the three holds settling, every command inside the envelope, decoupled turning the holds off and back on, propellant proportional to impulse, face in both modes ($<0.5°$ after 10 s), Level roll then pitch, the accumulator, and table tests of clock, height, range words and chips, including a 180° roll turning `12 high` into `12 low`. The suites carry no `# FT:` tags; the ids are in comments for the promoting issues.

`taskset -c 1,9 tools/gate.sh ci` passes (L0 and L1).

## Build for the owner

`export_presets.cfg` has a Linux preset "S5 Helm prototype" with the custom feature `s5`, and `project.godot` sets `run/main_scene.s5` to the prototype, so the build opens it while the normal exports are unchanged (the Linux game export still runs the server stub). The preset exports all resources except `tests/`, `tools/`, `docs/` and gdUnit4, so it also carries any other spike folders; they are inert.

```
godot --headless --path . --export-release "S5 Helm prototype" <path>/full-theta-s5-helm.x86_64
```

The build (74 MB, not in the repo) is `full-theta-s5-helm.x86_64` in the issue's artefacts. On any Linux desktop with OpenGL 3.3, run `./full-theta-s5-helm.x86_64`; the mouse is captured at once, Esc frees it. From a clone instead: `godot --path . res://spikes/s5/helm_prototype.tscn`. Arguments after `--`: `--s5-autopilot` flies the intercept as a demo, `--s5-no-help` hides the overlay, `--s5-quit-after=S` quits after S seconds with a summary line, `--s5-screenshot=PATH` saves the window before quitting. `timeout 15 ./full-theta-s5-helm.x86_64 --headless -- --s5-quit-after=5` exits 0 after 300 ticks; under Xvfb and llvmpipe it renders, and the screenshots were taken that way.

For the T013 playtest and the NAV-3 drill (#4): the intercept timer gives "intercept H2 in under 60 s" directly; "face H2" is T then hold F; "bring us to Bravo and stop within 1 km" is select Bravo, hold X, and the Bravo chip gives the range; "Level" is L; a roll-then-face recovery is Q or E for a few seconds, then hold F. Backspace restarts.

## What to promote

- **T027:** `S5Integrator` and `S5ShipBody` as they are. One change is needed for T027's own criterion: semi-implicit Euler's position after constant thrust is off from $\tfrac12 a t^2$ by $\tfrac12 a t\,\Delta t$, a relative error of $\Delta t / t$ ($1.7 \times 10^{-3}$ at 10 s), so "within 1e-6 relative" can't pass. Use $x \mathrel{+}= v\,\Delta t + \tfrac12 a\,\Delta t^2$ with the old velocity (exact under constant force, still velocity-Verlet for constant thrust) or compare against the discrete sum. The rotation uses the exact exponential update rather than $q \mathrel{+}= \tfrac12 \omega q \Delta t$, and skips rates under $10^{-9}$ rad/s because `Vector3` is float32.
- **T028:** `S5Assist` and `S5HelmState`, the world's edge handling, and the tuning above as starting data. Per-axis clamping bends the commanded direction when several axes saturate; fine in play, worth a note in the tests.
- **T034 (#5):** `S5Callout` and its table tests.
- **T050, T051 (#7):** `S5Radar` and `S5Compass` show the shapes and the data they need (ship-frame offsets, colour, selected, mark); rebuild them on the real theme and screenshot tests. `S5InputMapper`'s run-time actions and View chords are a model for the Helm intent layer, not code to keep.
