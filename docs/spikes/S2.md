# S2: llvmpipe screenshot harness under Xvfb

Run on fugaku (i7-11800H, Ubuntu 26.04.1), 2026-10-19, Godot 4.7.2-stable, Compatibility renderer, pinned to CPUs 6, 7, 14 and 15 with `LP_NUM_THREADS=4` (R2, FT-TST-003, FT-TST-020).

## Setup

| Package | Version |
|---|---|
| `xvfb` (installed for S2) | 2:21.1.22-1ubuntu1.2 |
| `mesa-utils` (installed for S2, `glxinfo` only) | 9.0.0-2build1 |
| `libgl1-mesa-dri`, `mesa-libgallium` (already present) | 26.0.8-1ubuntu0.3 |
| llvmpipe | LLVM 21.1.8, 256 bits |

Godot reports `OpenGL API 4.5 (Core Profile) Mesa 26.0.8-1ubuntu0.3 - Compatibility - Using Device: Mesa - llvmpipe (LLVM 21.1.8, 256 bits)`. The "256 bits" is the SIMD width llvmpipe picks for the CPU (AVX2), so a machine without AVX2 counts as a different environment.

## Harness

`tools/gate.sh l5` runs `tools/l5.py`, which starts Godot (not headless) under `xvfb-run -a` with `LIBGL_ALWAYS_SOFTWARE=1`, `GALLIUM_DRIVER=llvmpipe`, `--rendering-driver opengl3` and a fixed 640x360 window. `tools/l5_capture.gd` (a `SceneTree` script) instances each shot's scene in the root window, waits 5 frames and `frame_post_draw`, then saves the root viewport as an RGB PNG. All shots run in one Godot process. Shots are listed in `tests/visual/shots.json`; a shot names a scene and optional properties set on its root before it enters the tree, which is how one view scene gives several camera angles. `tests/visual/baselines/.gdignore` keeps Godot from importing the baselines as textures.

`l5.py` then checks the environment and diffs the pixels in Python (stdlib only, with a small PNG reader, so `tools/pyproject.toml` is unchanged):

- `baselines/env.json` holds the renderer string (llvmpipe and LLVM version), the GL version string (Mesa version) and the engine version, from `RenderingServer.get_video_adapter_name()`, `get_video_adapter_api_version()` and `Engine.get_version_info()`. If any differs, L5 fails with "baseline environment changed: …" and no pixel diff (FT-TST-020). The engine version is included because an engine upgrade shifts rendering as much as a Mesa upgrade (provisional).
- A pixel differs when any channel differs by more than 8 (of 255); a shot fails when more than $10^{-4}$ of its pixels differ (23 pixels at 640x360). A failing shot leaves `build/l5/<name>.diff.png` with the differing pixels in red (provisional values, see below).
- A capture fails outright when the renderer isn't llvmpipe, the image size is wrong, or the image is one flat colour.

`tools/gate.sh l5 --update-baselines` regenerates every baseline and `env.json`; `tools/l5.py --capture-only DIR [--shots FILE]` renders without comparing (S8 used it for the owner's screenshots). `ci` stays `l0 l1`; `all` is now `l0 l1 l5 l6`.

The fixture tests in `tools/tests/test_l5.py` (run by L0, no Xvfb needed) cover the PNG reader against a real baseline, identical and within-tolerance shots, a shot over the limit, a missing baseline, a size change, the blank check, and "baseline environment changed" for a Mesa change and for an llvmpipe change.

## Shots

The L5 baselines are the S2 scene (an orange torus lit by a directional light, and a panel with a label and a button, fixed camera, no animation) and the S8 ship from three angles, so the gate covers a UI panel, a standard material, the toon shader and the outline pass. Each baseline is 9–15 KB.

## Sensitivity

The tolerance was first $10^{-3}$ of the pixels. Changing the label from "thrust 42 %" to "thrust 43 %" changed 66 pixels (0.029 %), which that limit let through, so it is now $10^{-4}$, and the same change fails. Narrowing the S8 outline from 0.05 to 0.045 units changes 934–1,500 pixels per view and fails. Since llvmpipe gave zero noise, the tolerance only has to absorb changes nobody would call a regression; if a future scene is noisy, a per-shot override in `shots.json` is the cheap extension.

## Risks and notes

- fugaku has `unattended-upgrades` enabled. A Mesa or LLVM update from the security pocket changes `env.json` and fails every shot with "baseline environment changed" (TECH-11). Holding the Mesa packages (`apt-mark hold`) would avoid surprise failures at the cost of manual security updates (question in the report).
- L5 depends on fugaku's CPU and packages, so it stays off CI, as FT-TST-003 and §12.1 plan. A GitHub runner would also differ in llvmpipe's SIMD width and Mesa version, and fail the environment check.
- The harness renders the desktop build under Xvfb only. Web-only differences (fonts, DPI, WebGL2 precision) are left to the #9 Playwright smoke check (FT-TST-021).
- The baselines are the only PNGs in the repo; at 640x360 with flat toon colours they stay around 10 KB each.
